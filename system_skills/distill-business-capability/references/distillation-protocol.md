## 能力架构

一个可移植业务场景源码树包含三类 Skill：

| 类型 | 数量 | 唯一责任 |
|---|---:|---|
| 场景总控 | 1 | 识别整个场景请求，按已验收流程路由阶段和基础能力 |
| 阶段 Skill | 每流程阶段 1 个 | 完成一个稳定业务责任并交付阶段输出 |
| 基础 Skill | 按格式和外部系统 0-N 个 | 读取/解析文件或调用已声明知识服务，不作业务判断 |

禁止把所有阶段合成一个万能 Skill。第三方 Agent 需要通过描述判断何时调用能力；职责过大会让任意请求都触发同一个 Skill，也无法独立验证阶段输入输出。

## 流程阶段到 Skill

每个阶段 Skill 保留以下已验收事实：

- `objective` 与 `outcome`；
- 宏观输入和输出关系节点；
- 前置与后续阶段；
- 适用控制；
- 与本阶段相关的待确认项；
- 需要的基础文件能力。

每个阶段都携带 `scripts/run_stage.py`：先生成有摘要的工作单，再由 Agent 调用已声明基础 Skill、完成业务推理，最后校验必需输出并生成交接文件。运行器必须拒绝把原始大表、PDF、图片或 Office 文件当作阶段输入；完整结果只以带摘要的导出产物引用交接。

`procedure` 只将这些事实组织为可执行顺序。每个 procedure 项必须引用流程阶段、输入输出节点、控制、状态或交接 ID。没有来源的“人工审批”“通知负责人”“写入系统”“退回修改”等常识步骤不得加入。

阶段 Skill 的 description 必须包含：

1. 当前业务场景名称；
2. 本阶段负责形成的结果；
3. 哪类用户请求或上游交接会触发；
4. 明确不负责相邻阶段。

## 基础文件能力选择

基础能力只由已验收文件清单触发：

### tabular

适用 CSV、TSV、XLSX、XLS、XLSB、Parquet、JSONL、SQLite。使用随包 `operational-data-contract.json` 按当前操作注册多来源，以 DuckDB 做投影、过滤、连接、聚合和有限返回；Excel 优先使用 DuckDB `read_xlsx`，不可用时以 fastexcel 作为小文件后备。大 Excel 禁止使用会全表物化的后备路径。运行时只校验本次引用来源的路径边界和字段兼容性，不要求新批次文件与设计期样本大小或摘要一致；跨来源 SQL 先验证契约候选键组，并确认 SQL 的连接谓词实际使用同一键组。用户需要全量结果时写 CSV/Parquet 文件，只把行数、查询摘要和结果文件摘要交给 Agent。

表格、文档和 OCR 共享同一来源生命周期：

- `runtime_input`：按当前规则、阶段或查询实际需要时，通过 `source_id` 和相对路径绑定；
- `design_time_template`：历史结果或格式样例，只提供输出字段/章节、类型、定位和可选脱敏示例，原文件不进入运行时预检；
- `design_time_evidence`：只证明蒸馏依据，不生成运行时文件依赖；
- `optional_enrichment`：知识库、爬虫、Web 检索或远程 API，由 Agent 根据用户请求和完整规则判断是否调用。

场景定制必须写明：

- 实际出现的扩展名；
- 这些文件在关系图和流程中的业务角色；
- 哪些阶段先检索完整规则行、再验证单键或复合键、最后 preview/query/export；
- 大文件不能全量进入 Agent 上下文；
- 文件读取不等于业务判断。

### document

适用 TXT、Markdown、HTML、XML、JSON、YAML、DOCX、PPTX 和可搜索 PDF。工具必须流式/分段解析并建立本地检索索引；Agent 只接收有界命中。保留来源摘要、页码、段落、幻灯片或行号、chunk id 与文本摘要。PDF 文本层稀疏时转交 OCR。

### ocr

只在存在 PDF/图片、文档 Skill 返回 `ocr_recommended`，或明确知道材料为扫描件时生成和调用。保留原 `ocr-parser` 的：

- 本地路径、远程 URL 和 Base64 输入；
- 单文件与批量输入；
- 图片/PDF 参数区分；
- JSON 结构化输出和错误状态；
- 环境变量配置。

必须完整复制 `ocr-parser` 除通用 `SKILL.md`/UI 说明以外的脚本、依赖、配置和其他运行资源，重建场景专属 `SKILL.md` 和 `scenario_binding.json`。配置字段和值原样保留；平台凭据存储或当前环境已有的 Key 按原字段物化，不得清空或改写。

### knowledge

当已验收关系/流程包含明确的外部知识库节点时生成。完整继承 `vector-kb` 的脚本、依赖、配置、检索和原文定位能力，增加场景 CLI 并重建描述、触发条件、系统角色和场景约束。知识检索只补充相关阶段所需参照，不替代完整规则记录和结构化业务事实。需要时以 `--required` 调用；提供方报错或无结果必须输出 `manual_intervention_required`，交由人工提供或核验，不能生成替代事实。

## 规则不足时的处理

关系和宏观流程能证明职责边界，不一定包含执行每个判断所需的完整规则。此时：

- 把规则材料声明为运行时输入，由基础 Skill 读取；
- 把已验收 `control` 写入阶段约束；
- 把未解决条件保留为 `open_question_ids`；
- 缩小 Skill 能力陈述，避免声称能完成未证实的自动决策；
- 不从历史记录的高频路径反推出标准业务规则。

生成源码 `complete` 表示结构、覆盖和可移植性验收通过，不表示所有待确认业务问题已经解决。

## 场景总控

总控 Skill 不替代阶段 Skill。它负责：

1. 判断用户请求是整个场景还是单个阶段；
2. 先按完整规则记录确定数据需求，再根据输入格式调用基础 Skill；
3. 根据 `main_flow` 和 routing 调用阶段 Skill；
4. 在分支、返回或责任不明确时停止并暴露待确认项；
5. 传递阶段输出契约和可定位证据，不传递无关原始数据；
6. 表格链路先校验连接，非结构化材料先建索引；两类证据只有存在明确业务键时才可合并到同一实例。

总控携带 `scripts/orchestrate.py`，以小型状态文件确定下一主流程阶段、记录阶段 handoff，并允许已声明的可选阶段单独路由。Agent 不得临时编写流程状态管理脚本。

总控不能把流程主链之外的常识步骤塞入执行，也不能绕过阶段 Skill 自己完成所有业务判断。
